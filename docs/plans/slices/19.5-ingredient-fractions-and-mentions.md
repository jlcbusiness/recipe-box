# Slice 19.5: Ingredient Fractions and Mention Amounts

## Outcome

Make recipe quantities quicker to scan and instruction-linked ingredients
useful while cooking. US customary display uses familiar Unicode fraction
glyphs, and activating a structured ingredient mention reveals its current
recipe amount without leaving the instructions.

## Sources and existing behavior

- [Comprehensive reference § 3.1 and § 3.4](../comprehensive-reference.md#3-ingredient-rows-measurements-and-density)
  defines quantity input, customary fractions, metric decimals, scaling, and
  conversions.
- [Comprehensive reference § 5.1](../comprehensive-reference.md#51-instructions-editor-and-mentions)
  defines stable-ID ingredient mentions and their readable rendering.
- [Data model](../data-model.md#core-entities) makes mentions references to
  recipe-ingredient rows; no schema change is required.
- [Design philosophy](../design-philosophy.md#information-hierarchy-and-interaction)
  requires dismissible, viewport-bounded, keyboard-operable popovers.
- [Visual design](../visual-design.md#ingredient-presentation) records reader
  layout, scaling, unit conversion, and print behavior.
- [Slice 6](6-measurements.md) and [Slice 7](7-instructions-and-mentions.md)
  are the measurement and mention implementation precedents.
- Next.js 16.3.8's installed
  [Server and Client Boundary guide](../../../node_modules/next/dist/docs/01-app/02-guides/server-and-client-boundary.md)
  confirms serializable props and rendered elements can cross the server/client
  boundary. The interactive mention can consume reader state in the existing
  client provider without moving recipe data access to the browser.

## Scope

- Render the existing nearest customary fractions with Unicode glyphs for the
  supported denominators 2, 3, 4, and 8. Preserve the existing $0.03$ match
  threshold, mixed-number/range behavior, thousands grouping, and decimal
  fallback. Display glyphs slightly larger and vertically centered with
  optical corrections where font metrics require them. Metric quantities
  remain decimal.
- Preserve familiar fraction-text input and editor formatting such as `1/2`
  and `1 1/2`; cooks do not need to type glyphs. Also accept the corresponding
  glyphs as an optional parser round-trip convenience. Both forms serialize to
  the same numeric values, while Unicode glyph output is reserved for recipe
  reading and amount popups.
- In recipe detail, render each structured ingredient mention as an inline,
  keyboard-focusable button. Hover or focus reveals one compact popup; click or
  tap pins/toggles it. It contains only the current amount text, not another
  mention or tooltip.
- Derive popup values using the reader's current scale, default unit systems,
  and per-ingredient unit overrides. Show an unmeasured phrase when present;
  show `No amount listed` when the row has no amount or phrase.
- Dismiss on Escape, outside pointer interaction, or loss of hover/focus unless
  explicitly pinned; Escape returns focus to the trigger. Keep the bubble
  square with a strong ink-colored surface and a small comic-style pointer
  tail. Position it above the mention and clamp it within the visual viewport
  on desktop and mobile.
- Preserve the mention's sentence-aware readable text and current inline style.
  Print keeps the readable mention and current amount in the ingredient list,
  but never prints an open popup or its controls.

## Exclusions and boundaries

- No database, migration, RPC, history, export, or persisted preference change.
- No changes to instruction editing, mention serialization, public-link access,
  ingredient sorting, recipe content, or saved measurements.
- No popup for unstructured text or unresolved mentions; invalid structured
  references retain the current server-side failure behavior.
- No nested popup, additional ingredient details, or measurement editing from
  the bubble.

## State and recovery

Popup visibility and pinning are local transient UI state. Scale and unit
selection remain owned by `RecipeReaderProvider`; changing either updates an
open popup immediately. Reset restores the base recipe values through existing
reader behavior. Reload returns to the base state. Dismissal never changes
recipe data. A missing amount is a useful empty state, not an error; formatting
and positioning failures must not prevent reading the instruction text.

## Implementation notes

Keep one display formatter as the source of glyph output and extend the parser
for those exact glyphs. Pass only the serializable ingredient row needed by the
mention control from the Server Component; calculate the active amount in the
existing reader client boundary. Reuse the reader's viewport positioning
conventions, with a portal or equivalent positioning that cannot be clipped by
the instruction column.
