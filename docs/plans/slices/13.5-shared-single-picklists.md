# Slice 13.5: Shared Recipe Picklists

This slice adopts the shared portal `Picklist` for recipe metadata
single-selects and adds the recipe-specific `MultiPicklist` for multi-select
fields. `RecipeForm` coordinates both menu types so only one is open at a time.
Existing submitted values, metadata layout, conditional State behavior, and
account data remain unchanged; this slice introduces no database changes.

## Outcome

State, Enthusiasm, Verdict, and Food Type use the shared portal menu and its
keyboard, focus, dismissal, and viewport behavior. Meal Type, Cuisine, and
Equipment use the recipe-specific `MultiPicklist`, whose buttons toggle
multiple selected values. `RecipeForm` owns exclusive-open state across both
types. Existing single values and repeated multi-value IDs retain their form
names and serialization.

## Decisions

- Use shared `Picklist` for State, Enthusiasm, Verdict, and Food Type.
- Use the recipe-specific `MultiPicklist` for Meal Type, Cuisine, and
  Equipment. Its toggle-button interaction and repeated hidden ID inputs are
  distinct from the single-value shared `Picklist`.
- Add opt-in controlled visibility (`open` and `onOpenChange`). Existing
  callers that omit these props retain internally managed open state.
- Keep `RecipeForm`'s active picklist key as the source of truth for exclusive
  visibility across both implementations. Single-selects retain one named
  hidden input; multi-selects retain one `${category}_ids` hidden input per
  selected value.
- Preserve an empty prompt in the trigger and include it when sizing the
  trigger, so selecting or clearing a value does not cause layout shifts.
- Keep publication search and dialog pickers, ingredient typeahead, and
  specialized measurement UI out of this migration. The reader and Units
  already use the shared component; measurement menus already use its shared
  hook.

## UI And Interaction

- Triggers expose labeled combobox semantics and list options expose listbox
  option semantics, including the selected value.
- Arrow keys, Home, End, Enter, Space, Escape, Tab acceptance, outside-pointer
  dismissal, visible focus, and focus return after selection remain available.
- Multi-select groups expose a fieldset and legend; each trigger exposes its
  expanded state, and each option is a button with `aria-pressed`. Space
  toggles an option; arrow keys move option focus; Enter or Escape closes the
  menu and returns focus to its trigger.
- Single-select menus remain portal-rendered and viewport-aligned. Multi-select
  menus remain anchored to their trigger. Both menu types coordinate through
  the recipe form's exclusive-open state.
- Recipe metadata inputs, single- and multi-picklist triggers, Serves, and
  conditional Reason/Occasion Details controls remain 36px high on desktop and
  mobile, matching Name and Publication. Multi-picklist options have a 30px
  minimum on desktop and 36px on mobile. Distinct icon actions keep their
  separately specified hit areas.
- State changes continue to clear stale conditional values. Hidden inputs retain
  the current field names and selected values for form submission.
