# Slice 18.5: Recipe Tin as a Permanent Library Entry

This brief defines the conversion of Recipe Tin from an unparented recipe state
into a permanent, system-managed entry in the Library. Its user-facing role and
recipe behavior remain unchanged.

## Outcome

Each account has exactly one permanent Recipe Tin record in the Library. Recipes
that previously had no primary publication belong to that record. Recipe Tin is
always the first item among Library results that pass the active filters,
regardless of sort key or direction; filters, including the publication-type
filter, can exclude it normally.

## Decisions

- Store Recipe Tin as a reserved `collection` publication, displayed as
  `Recipe Tin`. The type is not offered by normal publication creation and the
  record cannot be renamed, edited, trashed, or deleted by the account owner.
- Create the record for existing accounts and automatically for new accounts.
  Enforce one record per account in the database. Use the mirrored,
  transparent `public/images/recipe-tin.webp` asset as its static cover.
- Migrate recipes with `publication_id IS NULL` to their account's Recipe Tin.
  Preserve recipe content, location fields, versions, and recipe history because
  membership is unchanged. After migration, recipe saves default to the Tin and
  database writes cannot leave recipes unassigned.
- Keep Recipe Tin as a container, not a source. Recipe detail says `In the
  Recipe Tin` instead of `From Recipe Tin`; no page or URL location is allowed.
- Apply Library search, type filters, field filters, and pagination normally.
  Order matching Recipe Tin first, then apply the selected sort to the remaining
  results. A Recipe Tin type filter returns the Tin; other type filters exclude
  it.
- Replace the separate Recipe Tin navigation destination with the Library
  entry. Keep `/recipes` as a compatibility redirect to the account's Tin detail
  route. New recipes default to the real Tin publication.
- Replace synthetic `__recipe_tin__` recipe-filter values with the Tin's
  publication ID, including persisted explorer filters.

## Scope

- Add a forward-only database migration for the reserved type, per-account
  provisioning, legacy recipe reassignment, write protections, search facets,
  and Library ordering.
- Update the recipe and publication type models, creation picker, publication
  detail, recipe attribution, Library filters, navigation, and compatibility
  redirects without changing ordinary Book, Magazine, or Site behavior.
- Add migration, owner-isolation, lifecycle, search/filter/sort, recipe-default,
  and desktop/mobile browser coverage.
- Update the product reference, data model, visual design, decision log, and
  roadmap after the behavior is verified.

## Test-First Acceptance

- An isolated migration test starts from the current schema, creates existing
  accounts and unparented recipes, applies this migration, and verifies one Tin
  per account, recipe backfill, unchanged recipe versions/history, and automatic
  Tin creation for a new account.
- Database tests prove owners cannot create, edit, trash, or delete the reserved
  Tin; normal publication types and their lifecycle remain unchanged; recipes
  cannot retain a null publication or attach a location to the Tin.
- Library browser tests verify Recipe Tin remains first under ascending and
  descending sorts, appears only when it passes the active type/field filters,
  and displays its mirrored cover in List and Grid.
- Recipe workflows verify new recipes default to the Tin, the picker selects it
  as a real publication, recipe detail uses `In the Recipe Tin`, and old
  `/recipes` links reach the Tin detail page.
- Search tests verify legacy Tin filter state is migrated or normalized, the
  Tin appears under its actual publication ID, and non-Tin type filters can
  exclude it.
- Chromium and Fold 6 accessibility checks cover the Library entry and
  publication detail, with no horizontal overflow.

## Implementation Status

Implemented and focused verification passed: isolated migration acceptance,

Biome and Markdown lint. The existing publication-lifecycle mobile width
