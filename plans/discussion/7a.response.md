That should be a second **ingredient presentation**, not a different data structure. I’d call it **Ingredient-first**. It says exactly what it does without inventing a cooking metaphor that may age badly.

**Ingredient-first** view:

| Ingredient | Amount | Preparation |
| --- | --- | --- |
| flour<br><small>all-purpose</small> | 1 cup / 254 g | |
| garlic<br><small>large</small> | 2–3 cloves | minced |
| salt | to taste | |
| coconut milk<br><small>14 oz</small> | 1 can | |

The Main checkbox stays edit-only because it is classification data, not an instruction the cook needs to read.

The existing view can remain **Standard**: ingredients in one column, amounts in a second, instructions in the third. Ingredient-first is the more task-oriented way to scan: acquire the thing, identify its specific form, measure it, then prepare it.

Make this a viewer preference rather than recipe data:

- Logged-in users can choose Standard or Ingredient-first, with a saved personal default.
- Print uses Ingredient-first by default because it is compact and intuitive on paper.
- Public pages use Ingredient-first, without exposing another interactive control beyond scaling, unit conversion, and print.

This keeps a recipe’s content stable while letting its presentation suit the person reading it.
