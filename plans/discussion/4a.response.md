**Vague Amounts**

I would not make “vague amount” a special mode the user has to discover. Give every ingredient row a small optional **Amount note** field alongside its structured quantities.

| Main | Ingredient | Preparation | Quantity | Amount note |
| --- | --- | --- | --- | --- |
| ☑ | salt |  |  | to taste |
| ☐ | onion | diced | `1` | large |
| ☐ | tomatoes |  | `2–3` | medium |
| ☐ | coconut milk |  | `1 can` | 14 oz |

The quantity area supports:

- **Count**: `1 cucumber`, `2–3 cloves`, `1 can`
- **Volume**: number + volume unit
- **Weight**: number + weight unit
- **Optional note**: “to taste,” “about,” “large,” “divided,” “14 oz can,” and so on

Only clean numeric volume/weight values participate in density conversion. Numeric counts scale too. Text-only or range amounts remain readable but do not pretend to be precisely convertible. The row can show both volume and weight plus an amount note when needed.

**Display Rounding**

I would interpret your preference as “use common fractions where they fit; otherwise show up to two decimal places,” not strictly two significant digits.

Examples:

- `0.5` → `1/2`
- `0.333…` → `1/3`
- `1.25` → `1 1/4`
- `0.625` → `5/8`
- `1.17` → `1.17`

Store values at full precision internally. The display formatter uses denominators `2`, `3`, `4`, and `8` where sufficiently close, then falls back to two decimal places. The editor can accept fractions, decimals, and mixed numbers.

**`#` References**

You are right to challenge the third option. It was a hedge against accidental linking, but it undermines the whole point of using references for reliable ordering.

Drop it.

Typing `#` in an instruction means “link an ingredient”:

- Select an existing ingredient.
- Type a new name and choose **Create ingredient**.
- Press `Escape` to cancel the reference action and continue writing normal text without the `#`.

A linked mention renders as normal readable ingredient text, while remaining structured underneath. Multiword typed references use hyphens only in the editor token: `#all-purpose-flour` displays as “all-purpose flour.”

**Size Sort**

Confirmed: ingredient sort has fixed groups in this order:

1. Volume, normalized to a base volume.
2. Weight, normalized to a base weight.
3. Count/unitless amounts, such as `1 cucumber`.
4. No usable amount or text-only amount.

Ascending or descending changes the order within each group; it does not mix volume, weight, and count into a fake shared scale.

**History**

I would remove version restoration from the first release. Keep an append-only change history for transparency, but do not build snapshots or restore controls yet. That avoids a surprisingly complicated feature while retaining the audit trail needed to add restoration later.

**Main Ingredients**

That is better than a separate metadata field. Add a **Main** checkbox to every ingredient row in edit mode. Checked ingredients populate the recipe’s searchable “main ingredients” index automatically.

It keeps the classification attached to the actual ingredient used, prevents duplicate entry, and naturally supports dishes whose essence is both chicken and lemon.
