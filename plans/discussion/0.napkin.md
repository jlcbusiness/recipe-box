- I like the layout, looks, and feel of Azure DevOps work items, and I like how they do queries, and I like how they integrate both with wikis. The problem is, they don't allow for- I believe it's called enums? Picklists with multiple values. And other things, but that was the deal-breaker. 
- I decided to try Fiberly. I really like how they handle databases and make everything db-backed and cross-linked. It make it really nice working between recipe books and recipes. But by all that is holy, I just hate the look and feel of the result. It's all panes, like they looked at Azure (not Azure DevOps) and thought "genius!" 
- I want... well, multiple things:
  - a recipe card, divided into parts:
    - the top, with all the recipe metadata 
      - name
      - source title (clickable, leads to recipe source in app)
      - page or URL (actually- it should display one or the other) (Urls are clickable)
      - food type (roast, pie, galette, caserole, pasta, soup, sauce, cake, cocktail, etc.) (single picklist you can add to)
      - meal type (breakfast, lunch, dinner, appetizer, side dish, snack, dessert, drink, booze, sauce, etc) (multi-select picklist you can add to)
      - cuisine (American, Italian, Chinese) (dropdown)
      - main ingredient(s) (chicken, beef, zucchini, lemon, garlic, etc.) - (multi-select picklist you can add to)
      - state (Want to try, tried, will not try)
      - verdict (if tried) (favorite, delicious, staple, once-a-year-rich, practice, try again, occasional, so-so, no, hell no, MISTAKE)
        - not specifically with those words or in that order - those are just the concepts/feelings/reactions
      - enthusiam (if not tried) (absolutely, sounds good!, try, situational, maybe, eh)
      - situation (if situational)
      - reason (if will not try) (text)
      - time(s) (only show what applies to the card)
        - chill/freeze/marinade time (should these be separate or selected?)
        - prep time
        - mixing time
        - cook time
        - bake time
        - cooling time
        - total time
      - servings
      - tools (use different name) (small/medium/large pan, bowl, baking sheet, skillet, spatula, whisk, hammer, peeler, etc)
    - 1st column, the ingredients (add from picklist you can add to)
    - 2nd column, the amounts 
      - you can enter both and either volume or weight, and it will show whichever has data
      - in edit mode, you enter a number and a unit, and the units can be any recognized unit (as long as they're in the category you're filling out, volume or weight - you can't put grams in volume or cups in weight)
      - in view mode, you can select unit you'd like to view the ingredient in, and it will show you the correctly-calulated amount (like cups to teaspoons to gallons)
      - also in view mode, you can adjust the recipe size. 
        - the recipe as entered is always 1. 
        - you can choose whether to multiply or divide
        - the default is multiply
        - if you chose multiply, it shows jx, where j is the integer you enter
        - if you chose divide, it shows 1/j, where j is the integer you enter
    - 3rd column, the instructions
    - the bottom row
      - pairs with (like, say, a sauce with a meat, or a side with an entree) (can be linked to multiple other recipes) (if you type #, auto-fill searches for existing recipes to link to as you type)
        - also shows any recipes that linked to this one 
      - notes for recipe improvements (or gotchas)
  - a recipe source (I'm not sure what to call this- source is terrible, but book is wrong when you use a site)
    - should show:
      - cover image (if book) (postage stamp size)
      - name
      - source type (book, magazine, site)
      - author (if book or magazine)
      - link (if site)
      - a list of recipes
        - clickable
        - show, in a line (below the title):
          - state
          - recipe type
          - food type
          - enthusiasm (if not tried)
          - verdict (if tried)
          - reason (if will not try)
          - total time
  - list of all recipes and sources
    - basically like a Azure Work Items query
    - filterable by any field
    - searchable by any field
    - sortable by any field
    - like I said, ADO WI query level of flexibility
  - a library of sources
    - should have windows explorer level of view and sort
    - grid, details, etc. 
    - it'd be pretty neat to have a preview pane like windows, too (obviously, without the recipe list)
  - settings
    - adjust all picklists (add/modify/delete/merge)
    - adjust all tags (add/modify/delete/merge)
    - any other settings you can think of
- misc
  - should be able to tag any recipe or source, and search on those tags
  - should be able to delete any recipe, obviously
  - should be able to delete any source, BUT, before you do, ask the user if the recipes inside should be deleted, unparented, or moved to another source
  - unparented recipes should be moved to the recipe box, which is where recipes with no known source live. It's like a recipe source, except it's a box. Or tin, rather. A tin box with a hinged lid. It's always got scraps of paper and dog-eared 3x5 index cards with handwritten notes. Obviously, not in digital form, but that should be its image, and the recipes should show have a ragged paper border as a background instead of a neat rounded square.
