# Slice 7.5: Reorder Interaction Polish

This brief improves the shared row-reordering experience after Slice 7 has
established instruction steps and their persistence. It changes interaction
feedback only: ingredient and instruction ordering, save payloads, stable IDs,
and history behavior remain unchanged. The product authority is [the
comprehensive reference](../comprehensive-reference.md), with related
boundaries in [the delivery roadmap](../delivery-roadmap.md), [the visual design
guide](../visual-design.md), [Slice 5: Ingredient Rows](5-ingredient-rows.md),
and [Slice 7: Instructions and Mentions](7-instructions-and-mentions.md).

## Outcome

A person can drag an ingredient or instruction row smoothly. The dragged row
has a clear elevated state, the destination is clear, and surrounding rows move
into place without a jump. Keyboard reorder remains available and produces the
same persistent order and accessible announcement. People who prefer reduced
motion receive functional feedback without unnecessary movement.

## Scope

Included:

- One reusable reorder interaction for ingredient rows and instruction steps.
- Smooth layout animation while a pointer or touch drag changes the prospective
  row position.
- A restrained lifted drag state and visible destination feedback that preserve
  the existing compact rail and row layout.
- Animated feedback when `Ctrl+ArrowUp` or `Ctrl+ArrowDown` changes a row's
  position.
- Touch, mouse, pointer-capture, scrolling, drag cancellation, and focus
  behavior verified on the supported desktop and Fold 6 viewports.
- `prefers-reduced-motion` behavior that preserves reordering feedback without
  movement-heavy transitions.
- Existing live announcements, visible focus, keyboard controls, and mobile
  touch target requirements.

Excluded:

- Changes to ingredient or instruction schemas, identifiers, position fields,
  save RPCs, history snapshots, or version-conflict behavior.
- New ordering modes, sorting, cooking views, print behavior, or settings.
- Any dependence on drag-and-drop alone; keyboard reorder remains equivalent.

## Design and implementation constraints

- First inspect the identified local implementation examples and verify their
  current package, browser, and accessibility behavior before selecting a
  library or implementation pattern.
- Keep the ingredient table semantic and preserve the compact numbered
  instruction rows. A drag preview must not obscure editable text or create
  horizontal overflow at 352px and 390px.
- Do not combine native HTML drag with captured pointer gestures. Use one
  interaction model per control and retain the existing deterministic drag
  tests as the baseline.
- A canceled drag leaves the current persistent order unchanged. A completed
  drag uses the existing stable-ID reorder path; animation must not be the
  source of truth for row order.
- Respect `prefers-reduced-motion: reduce`; disable positional transitions and
  use the destination state, focus, and live announcement to communicate the
  result.

## Acceptance tests

- Browser tests prove ingredient and instruction rows reorder by pointer and by
  `Ctrl+ArrowUp` / `Ctrl+ArrowDown`, reload in the saved order, and retain their
  existing content and stable IDs.
- Browser tests prove neighboring rows animate during a normal pointer drag and
  that the dragged row exposes a clear visual state without obscuring controls.
- Browser tests prove canceling a pointer or touch drag leaves the order
  unchanged, and dragging near viewport edges does not cause horizontal page
  overflow or unintended scrolling.
- Reduced-motion browser tests prove rows reorder correctly without layout
  transition animations.
- Desktop Chromium and Fold 6 axe checks report no WCAG 2 A/AA violations;
  keyboard focus, live reorder announcements, and delete controls remain
  usable.

## Verification

Run the focused ingredient-row and instruction-step browser tests, including
desktop Chromium and Fold 6 projects, without resetting the local Supabase
stack. Then run recipe accessibility checks, TypeScript typecheck, Biome, and
the relevant unit suite. Do not run `npm run dev:local` or any database-reset
command.

## Completion criteria

- Ingredient and instruction drag tabs share smooth, restrained reorder
  feedback on desktop and mobile.
- Keyboard and reduced-motion workflows remain fully functional and announce
  the resulting position.
- Reorder persistence, history, IDs, and save behavior remain unchanged.
- Focused browser, accessibility, typecheck, lint, and relevant unit tests
  pass.
